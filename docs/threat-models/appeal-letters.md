# Threat model: appeal letters (A2)

Scope: `src/domain/appeals/letter/`, `src/app/(app)/appeals/[id]/letter/` (editor and print view),
`src/app/(app)/settings/appeal-templates/`; tables `appeal_letter_templates`, `appeal_letter_versions`,
`appeal_letter_attestations` (`drizzle/0047_appeal_letters.sql`). Data: Restricted PHI by inheritance
(HC-1.2: appeal letters and free text). Spec: `docs/specs/appeals.md` A2. Standards: `docs/HIPAA_COMPLIANCE.md`
(HC-x.y), `docs/SECURE_CODING.md` (SC-x.y).

| Threat | Control | Residual risk / owner |
|---|---|---|
| Cross-tenant read or write of a template, letter, or attestation | Row-level security (`FORCE`, tenant policy) on all three tables; composite tenant FKs (a version must point at the same practice's appeal, an attestation at the same practice's version); every read and write runs in `withTenant`; isolation tests in `test/integration/tenancy.test.ts` | Low |
| A letter is sent to a payer without a person having read it (R-7.11.2) | Export renders only when the latest version has an attestation by a named user; a new version has none; attestation is refused while a `VERIFY` / `FILL IN` placeholder is left; the print view re-renders and compares a SHA-256 with the attested digest, so data that changed after review is refused; tests for each refusal | The attester may be the author (OA-096). Attestation proves a click by a named user, not that they read carefully |
| A letter or attestation is rewritten after the fact | `denialdesk_app` has `SELECT, INSERT` only on the two history tables (no `UPDATE`, no `DELETE`); BEFORE UPDATE OR DELETE triggers raise `appeal letter history is append-only` for every role, like `claim_versions`; `purge_demo_practices()` disables and restores them; tests assert `permission denied`; a save is a new version row | A superuser can disable a trigger (same as other append-only tables); WORM audit storage is a known gap (HC-5.3) |
| PHI stored where it need not be (HC-3.4) | The stored body keeps merge tokens; values are filled in when shown or printed, so a saved letter holds no copy of a name, birth date, or member ID; the member ID field is masked to its last four and the encrypted value is never selected or decrypted; columns are selected narrowly | A user can still type PHI into the body or a template; the UI says to use fields instead |
| PHI in audit rows, logs, URLs, titles, or file names | Audit metadata is version number, category, and a refusal reason code only; tests assert the letter text never appears in an audit row; the URL holds the appeal UUID; the page and print titles are generic (a saved PDF's suggested file name comes from the title); no logging of bodies | Low |
| Injection through a merge value or the body (HTML, script, or a token inside a value) | Rendering is one pass returning plain text: a value containing `{{...}}` is not expanded; the text is shown as a React text node (escaped); no `dangerouslySetInnerHTML`; a unit test renders `<script>` and `<img onerror>` and asserts they come out escaped | Low |
| Unknown or hostile merge field names (`__proto__`, `constructor`, a typo for a sensitive field) | Allow-list checked with `Object.hasOwn`; unknown or malformed tokens are refused at save, not passed through; no SSN, full member ID, or bank field exists as a merge field | Low |
| Lost update between two editors | The editor sends the base version; a save against a different latest version is refused; the appeal row is locked (`FOR UPDATE`) while the next version number is chosen; a unique index backs it | Low |
| Editing after the appeal was submitted | The domain refuses saves and attestations once the appeal is past draft, in review, or ready; the print view stays available for a reprint (attested, unchanged) | Low |
| Payer rule or law invented in a starter template (CLAUDE.md #9) | Starter text cites none; each spot holds a visible `VERIFY` / `FILL IN` placeholder that blocks attestation; a unit test scans the starters for citations | A practice can add a wrong citation to its own template; the reviewer's attestation is the control |
| Code inflation (CLAUDE.md #8, R-3.10.1) | Nothing in the letter path writes a claim, a denial, or a code; the coding starter says so and points to a separate human-approved correction | Low |
| Over-exposure inside the practice | Edit, attest, and export: admin, manager, specialist; compliance reads the letter but cannot change or export it; templates: admin and manager edit, all read; each checked on the server in the action and the page | Role matrix is a delegated decision, confirm with the owner (OA-096) |
| Print or export leaves no trace (HC-2.4) | Opening the print view is one audited export (actor, appeal, version); refusals are audited; the link is a plain anchor, so a router prefetch cannot trigger a false export | Printing from the browser after the page loads is not observable server-side; a reload is a second audited export |
| Cached PHI response (HC-2.3) | Pages are dynamic and authenticated; the root layout opts out of static rendering | Low |
| Stale template text or a typo at scale | A template change never alters an existing letter (a letter copies its body when started) | No template history yet (spec, A2 "Template versions"; OA-093) |
| New dependency risk (SC-A2) | None added. Print/PDF uses the browser's print dialog and Tailwind's `print:` variants | None |
| A sensitive patient's letter is exported before sensitivity handling exists (R-3.5.1, HC-1.5; OA-031, OA-091) | Attestation and export fail closed, audited with reason `sensitive_patient`, when the patient has any sensitivity tag, any source sensitivity label, or `source_restricted`; integration tests for a tag and for a source restriction, including an already-attested letter | Blocks all such patients from letters until the owner decides; counsel input pending |
| Printing the editor page bypasses review (S-M1) | The editor page is `print:hidden`; only `/letter/print` renders a printable letter, and only after the gate | **Residual:** copy and paste from the editor, a screenshot, or a browser "reader" view are not controllable; the audit trail records the page view (`appeal.letter_viewed`) only |
| A letter becomes permanently unprintable after data changes, or is re-approved silently | Attesting is allowed in any status; the newest attestation for the version wins and stores its own digest; a re-attestation with an unchanged rendering is refused; every attestation and refusal is audited | Low |
| A pre-production letter mistaken for a real one | Outside production the print page shows "SYNTHETIC / PREVIEW - NOT FOR SUBMISSION" on the printed page | Low |
| Unresolved data in the letter (`[not on file]`) is attested | Attestation is refused while any rendered field shows the marker | Low |
| Cached PHI response (HC-2.3), explicit | `next.config.ts` sends `Cache-Control: no-store` for `/appeals/:id/letter/:path*` (in addition to the dynamic-page default) | Low |
